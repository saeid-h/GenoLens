# GenoLens agent instructions

Single source of rules for every coding agent in this repository. Pointer files
(`CLAUDE.md`, `.cursorrules`) only redirect here—put new rules in this file.

## Orientation

- GenoLens is a **local** DNA report app: raw genomes stay on disk; analysis does
  not upload to third parties.
- Python analysis lives in `genolens/`. The HTTP API is under `api/`. The
  professional report UI is under `web/` (Next.js). Streamlit (`genolens/app.py`)
  is a legacy entry point.
- Private genomes: `data/*.txt`. Reference downloads: `data/reference/`. Both are
  gitignored. Never stage, commit, or push them.
- Start with `README.md` for how to run the stack; deeper guides live in `docs/`.

## Working agreement

- Reading, searching, and read-only commands need no approval (`git status`,
  `git log`, `git diff`, unit tests, listing samples).
- Before changing files, Git state, syncing dependencies, or contacting an
  external network service, state a short plan when the session requires
  approval; approval covers that plan only. A request to discuss or plan is not
  approval to edit.
- Never push, force-push, merge into `main` on the remote, or change remotes
  unless the owner asks.
- Ask if it is not clear; do not assume. Prefer a short clarifying question over
  guessing names, paths, scope, intent, or interfaces. When the owner delegates
  a choice, say that it was delegated.

## Commits

- **Commit after each logical stage** of implementation (do not wait to be asked,
  and do not batch an entire multi-step plan into one commit unless the owner
  says otherwise).
- **Never push** (or force-push) without the owner’s **explicit** consent in that
  turn. “Commit stages” alone is not permission to push.
- Stage **named paths only** — never `git add -A` or `git add .`.
- Never stage or commit: genomes under `data/`, `data/reference/`,
  `data/sample_meta.json`, `my-docs/`, `.env`, credentials, or build junk
  (`web/node_modules/`, `web/.next/`, `*.tsbuildinfo`).
- Message style: short subject focused on **why**; optional one-sentence body.
  Match recent `git log` on the branch. No emojis; no “Generated by …” footers
  beyond the project’s usual co-author trailers when already in use on `main`.
- Do not amend unless the owner asks (or a commit you just created in this
  session was auto-modified by a hook and has not been pushed).
- Never skip hooks (`--no-verify`). Never update git config.
- Do not create empty commits. If a hook rejects a commit, fix and create a
  **new** commit — do not amend the failed one.

## Repository boundaries

- Tracked code: `genolens/`, `api/`, `web/`, `tests/`, `docs/`, and config.
- Never store credentials, tokens, or absolute machine-only secrets in tracked
  files. Local overrides belong in ignored config (for example `.env`).

### `docs/` vs `my-docs/` — do not mix

| Path | Purpose | Git |
|------|---------|-----|
| **`docs/`** | **Public project documentation** for users of GenoLens (architecture, API, runbooks). | **Tracked** — commit and ship with the repo. |
| **`my-docs/`** | **Local and private** to the owner — personal agent knowledge base (sessions, decisions, private notes). | **Gitignored** — never stage, commit, copy into `docs/` or any tracked path, or upload. |

- Anything meant for public / repo readers belongs only in `docs/` (and short pointers in `README.md`).
- Personal memory / update-my-docs output belongs only in `my-docs/`.
- Never move, mirror, or “promote” `my-docs/` content into `docs/` unless the owner
  explicitly asks to publish a specific non-private excerpt.
- When `my-docs/` exists, read `my-docs/machine-friendly/index.json` first for
  local context. Nothing public users need may live only in `my-docs/`.

## Releases and versioning

- **Baseline release is `v0.0.0`.** Package / API version strings track that
  (currently `0.0.0`). A release means an annotated git tag `v0.0.0` (and later
  `v0.0.1`, `v0.1.0`, …) created only when the owner explicitly asks.
- **Status today:** Baseline **`v0.0.0` is released** (annotated tag + GitHub
  Release). Package / API version strings are `0.0.0`.
- **New features** start from the `v0.0.0` baseline (branch from the tag or from
  `main` at that tag) unless the owner directs otherwise. Prefer small,
  reviewable slices; do not treat every `main` tip commit as a new release.
- Never invent release tags or GitHub Releases without explicit owner consent.
  Pushing tags counts as a push — still requires explicit consent.

## Product rules

- Reports are **exploratory**, not medical advice, clinical diagnosis, or proof
  of descent from a named historical person.
- Never add a third-party genome-upload dependency to the default path.
- Compare / relatives: never auto-build an N×N matrix over every file in
  `data/`. The user picks one primary and selected candidates.
- Pedigree edges that need a generation direction must use IBD2 and/or
  user-supplied birth year / generation—not shared cM alone.

## Validation and handoff

- Run relevant tests after substantive changes (`pytest` for Python; API smoke
  tests when the API changes).
- Report the commands run, their results, and what was not verified (for
  example, no full AADR download or browser pass).
- Keep this file concise. Add a nested `AGENTS.md` only for a directory with
  genuinely different rules, and link it from here.
